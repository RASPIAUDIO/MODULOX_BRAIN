# loaderbrain

Prototype SD loader for Modulox ESP32-S3-WROOM-2-N32R16V modules.

The loader has three menu entries:

- `Install from SD`
- `Check WiFi updates`
- `WiFi status`

Build it with the existing firmware script, for example:

```powershell
.\script\build_firmwares.ps1 -Synth loaderbrain -NoData -Board esp32s3-octal -FlashMode opi -FlashSize 32M -CPUFreq 240 -PartitionScheme app5M_fat24M_32MB -USBMode hwcdc -CDCOnBoot cdc -UploadMode default -OutputDir .build\loaderbrain-firmware -BuildDir .build\loaderbrain-build
```

Flash the generated `loaderbrain-firmware-0x0-no-data.bin` at address `0x0`.

Boot behavior:

- `loaderbrain` lives in `app0`.
- Machines are installed in `app1`.
- After a machine has started, it immediately sets the next boot back to `app0`.
- On reset or power-on, the loader shows a 2 second auto-boot window, then boots the last installed machine in `app1`.
- Hold the bottom-right button during that 2 second window to stay in the loader menu.

The synths return to the loader by selecting `app0` and rebooting:

- From any packaged synth, hold the bottom-right button (`BUT3` / `GPIO38`) for 4 seconds.
- Release the button when the synth logs/confirms the hold.
- The module restarts on `loaderbrain` in `app0` and stays in the loader menu once.
- The encoder click (`BUTENCO` / `GPIO39`) is accepted as a fallback.
- `GPIO0` / `BUTLEFT` is not used for loader return because it is also the ESP32 ROM boot strap.

The SD card must contain the package generated by `script/package_loader_sd.ps1`:

```powershell
.\script\package_loader_sd.ps1 -Version 0.1.9 -VersionCode 10
```

This creates:

- `loader-sd/MODULOX/manifest.json`
- `loader-sd/MODULOX/wifi.json`
- `loader-sd/MODULOX/<machine>/app.bin`
- `loader-sd/MODULOX/<machine>/data.ffat.bin`
- `loader-catalog/catalog.json`
- `loader-catalog/<machine>/app.bin`
- `loader-catalog/<machine>/data.ffat.bin`

Packaged machines:

- `FMbrain`
- `granulizer`
- `organbrain`
- `sampbrain`
- `VAsynth`

For `raw` FFat images, the packaging script trims the unused tail of
`data.ffat.bin`. The loader still erases the whole `ffat` partition before
writing the image prefix, so stale data does not survive, but SD transfer time
is much shorter for machines whose data files occupy only the start of the
filesystem image.

During installation the loader releases the TFT SPI bus so the SD card can use
it. The screen can stay on `Installing ...` until the reset even though the
serial log is progressing. After a successful install, the loader stores the
selected machine as the auto-boot target, selects `app1`, and resets
automatically. Once the machine reaches `setup()`, it sets `app0` back as the
default boot partition for the next reset.

The first flash image for the loader is generated at:

```text
firmware-32MB-no-data/loaderbrain/loaderbrain-firmware-0x0-no-data.bin
```

To copy the generated SD package to a mounted SD card without formatting it:

```powershell
Copy-Item -LiteralPath .\loader-sd\MODULOX -Destination I:\ -Recurse -Force
```

Edit `loader-sd/MODULOX/wifi.json` on the SD card before using `Check WiFi updates`:

```json
{
  "ssid": "your-wifi",
  "password": "your-password"
}
```

Upload the contents of `loader-catalog` to `https://apps.raspiaudio.com/modulox/`.
The loader validates HTTPS with the embedded `apps.raspiaudio.com` CA and verifies every downloaded file with SHA256 before updating the SD manifest.
